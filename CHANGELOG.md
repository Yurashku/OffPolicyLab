# Changelog

## 0.3.0

Пакет переписан с нуля вокруг сценариев использования: одна точка входа, один путь
формул, одна пара nuisance-моделей на все оценщики и кандидатов.

### Корректность

- **Оценённые пропенсити больше не ломают оценку.** В 0.2 они оценивались in-sample без
  ограничения снизу. На ε-greedy логах это давало веса около 500 и RMSE(DR) = 7.7 на бинарной
  метрике при 0.03 на истинных пропенсити. Теперь пропенсити всегда out-of-fold и ограничены
  полом для каждого действия. RMSE падает до уровня логированных пропенсити, а отчёт показывает
  чувствительность к полу.
- **Честный интервал при оценённых пропенсити.** Аналитический интервал не учитывает ошибку их
  оценки, и при «остром» логировании его покрытие падало до 0.57–0.75. Поэтому
  `inference="auto"` в этом случае включает кластерный bootstrap с переобучением моделей.
- **Метки действий больше не могут молча перепутаться.** В 0.2 переставленные колонки политики
  давали неверный ответ без ошибки. Политика теперь — таблица с метками действий в колонках; она
  вычисляется один раз и сопоставляется по меткам.
- **Утечка исхода в признаки.** Колонка другой метрики (выручка при оценке принятия) почти
  идеально предсказывает награду. Авто-выбор такие колонки исключает, при явных `features`
  выдаётся предупреждение.
- **Входные данные.** NaN в награде и признаках — явная ошибка с подсчётом строк.
  Категориальные признаки кодируются one-hot.
- **Bootstrap.** Фолды cross-fitting внутри реплики группируются по исходной строке, поэтому её
  копии не попадают одновременно в обучение и прогноз.
- **Кластерно-робастная ошибка.** Добавлены поправка CR1 и t-квантили с G−1 степенями свободы.
- **DM больше не может быть основным оценщиком.** Его интервал недопокрывает истину; DM остался
  в таблице согласия.

### Диагностика и отчёт

- **Триангуляция оценщиков.** DR − IPS проверяет пропенсити, DR − DM — модель исхода. Провал
  засчитывается, только если расхождение значимо и существенно (больше 0.5·SE(Δ)), а в остальных
  случаях указывается граница.
- **Проверка колонки пропенсити.** Используется тождество E[1{A=a}/p] ≤ 1, поэтому ловится
  переданная вместо пропенсити вероятность отклика.
- **Детерминированная логирующая политика.** Проверяется, исследует ли A, и насколько B с ней
  совпадает. Дефицит носителя ловится через E[w] = 1.
- **Вердикт доверия блокирует вывод.** При «ненадёжно» отчёт не пишет «B лучше», как бы ни
  выглядел интервал.
- **Новые цифры в отчёте:**
  - относительный прирост с log-ratio-интервалом;
  - MDE для «разница не обнаружена»;
  - таблица перекрытия по действиям;
  - совет «что делать» к каждой находке.
- **Romano–Wolf.** Поправка на множественность по метрикам (а в `compare` — по кандидатам)
  учитывает их зависимость.
- **Представления результата.** Отчёт рендерится в Jupyter (`_repr_markdown_`), есть
  `summary()`, `to_json()` и стабильная схема `to_dict()`.

### Клиентский путь

- **API.** `ps.Evaluator(logs, action=..., reward=[...], propensity=..., cluster=...)`, затем
  `.evaluate(policy)` / `.compare({...})`; `ps.evaluate(...)` для одного вызова.
- **Политики.** На вход принимаются `DataFrame` вероятностей с метками действий, колонка или
  `Series` действий, объект с `action_probs`. Хелперы `ps.greedy`, `ps.softmax`,
  `ps.epsilon_greedy`.
- **Несколько метрик, кандидатов и база.** Модели обучаются один раз; `baseline` сравнивает
  B с прод-версией A.
- **Синтетика.** `ps.synthetic.OfferSimulator`: строковые офферы, категориальный регион,
  повторные визиты с клиентским эффектом, аналитический оракул.

### Проверка работоспособности

- **`tests/test_statistical.py`:** несмещённость, состоятельность, двойная робастность с
  негативным контролем, покрытие ДИ, кластерный инференс, регрессия на оценённые пропенсити,
  ложные тревоги и мощность проверок, контроль FWER.
- **`examples/validate.py`:** сценарии logged / softmax / weak_overlap / estimated / clustered
  против аналитической истины. Результаты — в `docs/validation.md`.

### Миграция с 0.2

| 0.2 | 0.3 |

| `OPEEvaluator`, `compare_policies_multi_estimator` | `ps.Evaluator(...).evaluate(policy)`: все оценщики в `report[metric].estimators` |
| `compare_policies_multi_target` | `reward=[...]` |

| `nuisance_spec=NuisanceSpec(...)` | `propensity_model=`, `outcome_model=` |
| `BanditSchema`, `LoggedBanditDataset` | аргументы `Evaluator` |

| `SyntheticRecommenderEnv`, `make_policy` | `ps.synthetic.OfferSimulator`, `sim.policy(...)` |

## 0.2.0

Крупная ревизия. Математика точечных оценщиков подтверждена как соответствующая
определениям Open Bandit Pipeline; исправлен слой вокруг них, где накопились
молчаливые деградации, и добавлена проверка корректности против известной истины.

### Исправления корректности

- **Утечка награды в признаки.** Автовыбор признаков исключал зашитый список имён
  и игнорировал фактический `target`, поэтому при нестандартном имени колонки
  награда попадала в признаки nuisance-моделей, произвольно смещая DM/DR.
  Теперь исключаются фактические `target`/`action_col`/`cluster_col`/`propensity_col`,
  а явное указание награды в `feature_cols` отклоняется с ошибкой.
- **Тип модели исхода определяется по данным**, а не по литералу `target == "accept"`.
  Бинарная награда под любым именем получает классификатор.
- **Взаимодействия `x*a` в модели исхода.** Раньше `mu(x,a)` имела общий наклон
  и различалась между действиями только сдвигом, то есть структурно не могла
  выразить зависящий от действия эффект.
- **Неизвестное действие больше не молчит.** Подстановка `pi_A = 1e-6` порождала
  веса порядка `1e6`; теперь доля таких строк считается, попадает в диагностику
  и вызывает предупреждение. One-hot энкодер обучается на полном `action_space`,
  а не на наблюдённых действиях с `handle_unknown="ignore"`.
- **Cross-fitting учитывает кластеры**: фолды формируются по `cluster_col`, иначе
  строки одного пользователя попадали и в train, и в holdout.
- **Cross-fitting не подменяет логированные пропенсити** модельной оценкой: они
  точны и в поправке на переобучение не нуждаются.
- **Проверка пропенсити ловит NaN** (`nan <= 0` и `nan > 1` оба False, поэтому
  наивная проверка диапазона пропускала NaN в веса).
- **`weight_clip` применяется к `switch_dr`** — раньше молча игнорировался.
- **SNIPS возвращает NaN** при нулевом перекрытии вместо правдоподобного нуля.
- **Схема датасета больше не перезаписывает явные аргументы**: вызов
  `compare_policies(dataset, ..., target="cltv")` считал метрику из схемы.
- **Проверка, что строки политики суммируются в 1** — иначе DM молча масштабировался.

### Инференс

- **Кластерный ресэмплинг ускорен примерно в 800 раз** (`O(C*N)` → `O(N)` на реплику);
  на 20k строк / 4k кластеров одна реплика занимала 1.5 с, теперь 1.8 мс.
- **Cross-fitting выполняется внутри каждой bootstrap-реплики.** Раньше точечная
  оценка была cross-fit, а интервал строился вокруг in-sample оценщика — то есть
  описывал другую величину.
- **Внешний `nuisance_bundle` несовместим с bootstrap** и теперь отклоняется явно:
  он привязан к конкретным строкам и не может быть пересчитан на реплике, так что
  интервал неизбежно описывал бы другой оценщик, чем точечная оценка.
- **Предупреждение о стоимости прогона**: bootstrap с переобучением nuisance на
  больших данных занимает минуты или десятки минут, и пользователь узнаёт об этом
  до запуска, а не после.
- **Добавлен аналитический CI** (`inference="influence"`) по построчным вкладам
  с кластерно-робастной дисперсией: один проход вместо сотен переобучений.
- **Формулы оценщиков вынесены в единый источник** (`estimator_contributions`),
  общий для точечной оценки и инференса.
- **NaN-реплики отбрасываются** со счётчиком вместо превращения всего CI в NaN.
- **Отсутствующая колонка кластеров — ошибка**, а не молчаливый откат к построчному
  bootstrap с антиконсервативными интервалами. При этом `cluster_col` по умолчанию
  теперь `None`: подставлять имя колонки, которой может не быть, значит ломать
  простейший вызов. Если в данных есть похожая на кластер колонка с повторами,
  библиотека об этом сообщит.
- `rng_seed` доступен из публичного API; `n_boot` по умолчанию повышен до 500.
- `ci_excludes_zero` приводится рядом с `is_significant`: это разные процедуры,
  и их расхождение теперь видно, а не скрыто.

### Отчёты и диагностика

- **Появился рендеринг результата**: `to_markdown()`, `to_frame()`, `to_dict()`.
- **Вердикт доверия** (`надёжно` / `с осторожностью` / `ненадёжно`) с расшифровкой
  предупреждений человеческим текстом.
- **Схема результата стабильна**: ключи присутствуют всегда, отсутствующие
  значения равны `None`.
- **Диагностика весов считается по фактически использованным весам** (после
  клиппинга), а не по исходным.
- Добавлены `mean_weight` (при верных пропенсити должен быть ≈1), `n_clusters`,
  покрытие по действиям и масса `pi_B` на неподдержанных действиях.
- Исправлен `top1_accuracy`: сравнивал индекс столбца с меткой действия.
- Метрики nuisance-моделей считаются out-of-fold, а не in-sample.
- Пороги предупреждений настраиваются (`DiagnosticThresholds`).
- `compare_policies_multi_estimator` сводит оценщики в одну таблицу.

### Проверка работоспособности

- **Аналитический оракул** в синтетической среде. Раньше эталон сэмплировался,
  и его собственная ошибка была сопоставима с измеряемым смещением оценщиков.
- **Новый набор тестов корректности**: точные значения формул, тождества между
  оценщиками, несмещённость, состоятельность, двойная робастность (с негативным
  контролем) и фактическое покрытие CI.
- Валидационная обвязка получила пороги приёмки и метод `check()`. Проверка покрытия
  учитывает монте-карло-погрешность самой оценки покрытия: без этого при десятке
  прогонов она срабатывала бы случайно, и её пришлось бы отключить.
- Обвязка принимает `nuisance_spec` и `feature_cols`, что позволяет прогнать
  оценщики при заведомо ослабленной модели исхода и увидеть, что оценка DR при
  верных пропенсити от этого практически не меняется.

Что показали прогоны (30 повторений, ε-greedy логирование):

- с логированными пропенсити смещение IPS/DR/SNDR ниже 3 SE, покрытие 95% CI — 0.97;
- **оценённые пропенсити на почти детерминированной логирующей политике
  разваливаются**: RMSE для `Delta` вырастает с 0.05 до 141, покрытие падает до 0.63.
  Логистическая модель не воспроизводит ступенчатые вероятности ε-greedy политики.
  Библиотека помечает такие прогоны как ненадёжные; это задокументировано в README
  как главный практический аргумент сохранять `propensity` при логировании;
- DM после добавления взаимодействий `x*a` на этой синтетике специфицирован верно
  и даёт лучший RMSE, но его аналитический интервал недопокрывает (0.77) — что
  подтверждает задокументированное ограничение `inference="influence"` для DM.
- В CI добавлены `pytest` (раньше он нигде не устанавливался), матрица версий
  Python, coverage и отдельная job для медленных статистических проверок.

### Клиентский путь

- **Адаптеры политик**: `TabularPolicy`, `DeterministicPolicy`, `SoftmaxPolicy`,
  `EpsilonGreedyPolicy` — включая устойчивость к подвыборкам через выравнивание
  по индексу. Раньше все встроенные политики были зашиты на признаки синтетики.
- **Публичный API экспортируется из корня пакета** (`import policyscope as ps`).
- `OPEEvaluator` доведён до паритета: `propensity_source`, `use_crossfit`,
  `rng_seed`, `nuisance_spec`, `compare_all()`.
- **Подключаемые nuisance-модели** через `NuisanceSpec`.
- Библиотека больше не вызывает `logging.basicConfig` при импорте и не печатает
  сотни строк в горячем цикле bootstrap.
- Добавлен `py.typed`.

### Удалено

Консолидация API: четыре пересекающиеся точки входа с тремя разными форматами
ответа сведены к одной.

- модуль `policyscope.bootstrap` (чистый форвардинг в `inference`);
- модуль `policyscope.ci` → переименован в `policyscope.estimate`;
- `estimate_value_with_ci`, `estimator_with_bootstrap_ci`, `ate_from_values`;
- `report.analyze_logs`, `report.decision_summary` (заменены рендерером);
- параметр `with_ci` (заменён на `inference="bootstrap"|"influence"|"none"`);
- параметр `method` у точек входа инференса (не влиял ни на что).

### Гигиена

  а блобы в LF, из-за чего `git status` показывал все 39 файлов изменёнными
  (8840 строк фантомного диффа).
- `.gitignore`, dev-зависимости в `pyproject.toml`, конфигурация pytest.
