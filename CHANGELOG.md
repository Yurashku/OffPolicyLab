# Changelog

## 0.3.0 (не опубликована)

Первая версия, подготовленная к публикации на PyPI. Пакет переписан с нуля вокруг сценариев
использования:
- одна точка входа;
- один путь формул;
- одна пара nuisance-моделей на все оценщики и кандидатов.

### Что внутри

- **API.**
  - `ps.Evaluator(logs, action=..., reward=[...], propensity=..., cluster=...)`, затем
    `.evaluate(policy)` или `.compare({...})`;
  - `ps.evaluate(...)` для одного вызова;
  - политика B — таблица вероятностей с метками действий в колонках, колонка или `Series`
    действий, либо объект с `action_probs`;
  - хелперы `ps.greedy`, `ps.softmax`, `ps.epsilon_greedy`;
  - несколько метрик и кандидатов на одних моделях; `baseline` — сравнение с прод-версией A.
- **Оценщики.**
  - Основной выбирается автоматически (`estimator="auto"`), и отчёт объясняет выбор; сейчас это DR.
    SNDR, IPS, SNIPS — по явному выбору; DM — тоже только явно.
  - Все оценщики считаются из одних cross-fit моделей и показываются в таблице согласия.
  - Модель исхода выбирается по данным: логистика, двухчастная модель для выручки или Ridge;
    можно задать свою модель для каждой метрики.
  - Модель пропенсити по умолчанию выбирается по out-of-fold log-loss: логистическая регрессия с
    подобранной регуляризацией или градиентный бустинг. Без подбора регуляризации логистическая
    модель переобучалась на разреженных признаках (Open Bandit Dataset). Без бустинга ступенчатые
    правила (argmax скоринга, смесь версий) давали ложное перекрытие.
  - Блок взаимодействий x×a отключается, только если не помещается в память (много действий и
    признаков). Бинарные логистические регрессии на узкой матрице решаются методом Ньютона:
    быстрее и точнее lbfgs.
- **Политики и логи.**
  - `ps.uniform()`, `ps.random_like(source, by=...)` — случайная выдача, в том числе с балансом
    наблюдаемой политики в целом или внутри групп (по месяцам); `ps.mixture(...)` — смесь политик.
  - `logging_policy=`: известная политика A вместо колонки пропенсити — пропенсити считаются точно;
    `ev.support()` и `allowed=` у `ps.greedy`/`softmax`/`epsilon_greedy` — оценка варианта модели в
    пределах уже показанных действий; точная доля решений вне покрытия логов в отчёте.
  - Авто-выбор признаков пропускает даты строкой и колонки с метками действий; колонка кандидата
    в признаках — ошибка.
  - Логи нескольких политик (`logging_policy={метка: политика}`, `logger=`): пропенсити по смеси
    (balanced IPS), проверки состава клиентов и сезонности отклика между периодами.
- **Инференс.**
  - Аналитический интервал с кластерно-робастной ошибкой (CR1, t с G−1 степенями свободы).
  - Bootstrap с переобучением моделей — автоматически при оценённых пропенсити и для DM; перед
    стартом — прогноз длительности, откалиброванный на реальных прогонах.
  - Относительный прирост с log-ratio-интервалом, MDE.
  - Поправка Romano–Wolf по метрикам и кандидатам.
  - Соревнование кандидатов: одновременные интервалы, попарные сравнения, набор лучших и
    ограничители (`Leaderboard.best`).
- **Диагностика и отчёт.**
  - Вердикт доверия; при «ненадёжно» вывод не делается; причина названа в первой строке отчёта.
  - V(A) и V(B) с интервалами в главной таблице и в `summary()`.
  - Проверки DR − IPS и DR − DM и итог «согласованы / расходятся / проверка неполная» с разбросом
    Δ по всем оценщикам.
  - Проверка колонки пропенсити, детерминированности A, дефицита носителя, ESS, утечки исхода в
    признаки, постоянной метрики.
  - Каждая находка — с цифрами и советом; таблица кодов — в `docs/methodology.md`.
  - Отчёт рендерится в Jupyter; есть `summary()`, `to_json()` и стабильная схема `to_dict()`.
- **Синтетика и валидация.**
  - `ps.synthetic.OfferSimulator` с аналитическим оракулом.
  - Статистические тесты: несмещённость, покрытие, двойная робастность, кластерный инференс, FWER.
  - `examples/validate.py` — восемь сценариев; результаты в `docs/validation.md`.
  - Исследование выбора оценщиков — `docs/estimators.md`.
  - Туториал `examples/tutorial.ipynb` начинается с основного сценария (пропенсити не залогированы)
    и сверяет каждый результат с истиной; `examples/monthly_versions.ipynb` — ежемесячные версии
    скоринговой модели.
  - Основной сценарий на открытых реальных данных с известной истиной (Hillstrom, Open Bandit
    Dataset) — `examples/real_data.py`, результаты в `docs/real_data.md`.
- **Совместимость.** Python 3.10–3.14; нижние границы зависимостей проверяются в CI.

### Исправлено по сравнению с 0.1

- **Оценённые пропенсити.** Раньше они оценивались in-sample без ограничения снизу. На ε-greedy
  логах веса доходили до сотен, и ошибка DR была в сотни раз больше, чем с истинными пропенсити.
  Теперь пропенсити всегда out-of-fold и ограничены полом для каждого действия, а отчёт показывает
  чувствительность к полу.
- **Интервал при оценённых пропенсити.** Аналитический интервал не учитывает ошибку их оценки
  (покрытие 0.75–0.93 в симуляциях). Теперь в этом случае по умолчанию используется bootstrap с
  переобучением моделей: на базовой паре политик покрытие 0.92–0.97. Ограничения режима — в
  `docs/validation.md`.
- **Метки действий.** Переставленные колонки политики давали неверный ответ без ошибки. Теперь
  сопоставление идёт по меткам, а неоднозначное сопоставление строк — явная ошибка.
- **DM.**
  - Прежний аналитический интервал DM не учитывал ошибку модели исхода: покрытие было 0.61–0.77.
  - Обрезка прогнозов и линейная модель для выручки смещали DM на величину до нескольких его
    стандартных ошибок.
  - Теперь DM считается двухчастной моделью без обрезки, имеет честный bootstrap-интервал и
    выбирается явно.
- **Входные данные.**
  - NaN в награде и признаках — явная ошибка.
  - Категориальные признаки кодируются.
  - Колонка другой метрики не попадает в признаки.
- **Bootstrap и cross-fitting.**
  - Фолды внутри реплики группируются по исходной строке.
  - Кластерный ресэмплинг стоит O(n) на реплику.

### Переход с версии 0.1

| 0.1 | 0.3 |
|---|---|
| `compare_policies(df, policyB, target=..., action_col=..., cluster_col="user_id", propensity_col=...)` | `ps.evaluate(df, policy, reward=..., action=..., cluster=..., propensity=...)`; кластер теперь указывается явно (по умолчанию его нет) |
| `OPEEvaluator(...).evaluate(estimator)` | `ps.Evaluator(...).evaluate(policy, estimator=...)`; все оценщики — в `report[metric].estimators` |
| `compare_policies_multi_target` | `reward=[...]` |
| `with_ci=False` | `inference="none"` |
| `use_crossfit=True` | всегда |
| `propensity_source="logged" / "auto"`, `propensity_col=` | `propensity=` (колонка) или `None` (оценка моделью) |
| `rng_seed=`, `crossfit_random_state=` | `random_state=` |
| `n_boot=300` | `n_boot=200` (bootstrap нужен только при оценённых пропенсити и для DM) |
| `DeterministicActionColumnPolicy` | имя колонки действий как политика: `ev.evaluate("chosen_offer")` |
| `make_policy`, `GreedyUnknown`, `EpsilonGreedy`, `SoftmaxFromScores` | `ps.greedy`, `ps.softmax`, `ps.epsilon_greedy` над таблицей скоров |
| `BanditSchema`, `LoggedBanditDataset` | аргументы `Evaluator` |
| `SyntheticRecommenderEnv`, `SynthConfig` | `ps.synthetic.OfferSimulator`, `sim.policy(...)` |
| `switch_dr`, `replay`, `weight_clip`, `on_policy` | удалены; причины — в `docs/estimators.md` |

## 0.2.0 (не опубликована)

Промежуточная ревизия, не выходившая за пределы ветки разработки:
- исправления корректности вокруг оценщиков;
- аналитический интервал;
- первые тесты корректности против известной истины.

Всё содержимое вошло в 0.3.0 в переработанном виде.

## 0.1.0

Первая версия: генерация синтетики, политики, оценщики IPS/SNIPS/DM/DR/SNDR/Switch-DR,
кластерный bootstrap, диагностика, обвязка валидации.
