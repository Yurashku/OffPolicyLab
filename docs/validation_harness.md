# Обвязка валидации на синтетике

`policyscope.validation.run_simulation_validation(...)` запускает повторяемые
синтетические эксперименты и сравнивает оценки с **истиной, известной аналитически**.

## Почему эталон точный

`SyntheticRecommenderEnv.oracle_value` для бинарной метрики считает
`mean_i sum_a pi(a|x_i) p(x_i, a)` в замкнутой форме — без сэмплирования действий
и отклика. Это принципиально: если эталон сам зашумлён, его ошибка складывается
с ошибкой оценщика, и измеренное «смещение» перестаёт что-либо означать.

Для CLTV интегрирование по действиям и по бернуллиевскому отклику тоже
аналитическое; методом Монте-Карло берётся только гауссовский шум, который не
убирается из-за усечения. Оракул использует отдельный генератор случайных чисел,
поэтому его вызовы не влияют на генерацию логов.

## Что измеряется

По каждому прогону: оракульные `V_A`, `V_B`, `delta`; оценки; смещение и
абсолютная ошибка; накрывает ли `Delta_CI` истину; ширина интервала; значимость;
диагностика (`ESS/N`, средний вес, p99 веса) и число предупреждений.

Агрегат по паре «режим × оценщик»: среднее смещение, RMSE, стандартное отклонение,
фактическое покрытие CI, доля значимых решений и средние диагностики.

## Приёмка

`ValidationResult.check()` сравнивает агрегат с порогами `ValidationThresholds`
и возвращает список нарушений:

- смещение `delta` не должно превышать заданное число стандартных ошибок;
- фактическое покрытие 95% интервала должно лежать в допустимом коридоре.

По умолчанию проверяются только `ips` и `dr` — оценщики, несмещённые **в конечной
выборке** при верных пропенсити. Осознанно исключены:

- `snips` и `sndr` — самонормированные, а значит смещённые в конечной выборке
  по построению: это их сознательный размен смещения на дисперсию;
- `dm` — его точность целиком определяется тем, насколько верно специфицирована
  модель исхода, и не является свойством библиотеки;
- `replay` — оценивает другую величину.

Отдельная проверка показывает наблюдаемое следствие двойной робастности: при
верных пропенсити оценка DR практически не меняется, если лишить модель исхода
ключевых признаков, — IPS-поправка компенсирует её ошибку.

Чего обвязка сознательно **не** утверждает — что «DR точнее DM». На этой среде
DM остаётся почти несмещённым даже при грубой модели исхода: он усредняет `mu`
по популяции, и поточечные ошибки в среднем гасятся. Более того, при корректной
модели исхода DM даёт лучший RMSE, потому что DR платит дисперсией за поправку.
Строгое доказательство двойной робастности — с подстановкой заведомо неверных
nuisance и негативным контролем, подтверждающим, что проверка вообще способна
поймать смещение, — находится в `tests/test_estimator_correctness.py`.

## Пример

```python
from policyscope.validation import ValidationMode, run_simulation_validation

result = run_simulation_validation(
    n_runs=20,
    n_users=2000,
    n_boot=200,
    estimators=("ips", "snips", "dm", "dr", "sndr"),
    modes=(
        ValidationMode(name="logged", propensity_source="logged"),
        ValidationMode(name="estimated", propensity_source="estimated"),
        ValidationMode(name="crossfit", propensity_source="estimated", use_crossfit=True),
    ),
)

print(result.aggregate)
problems = result.check()
print(problems or "все проверки пройдены")
```

Запуск из командной строки:

```bash
python examples/run_validation_experiment.py --n-runs 20 --n-users 2000
```

## Что показывают текущие прогоны

30 повторений, 2000 пользователей, ε-greedy логирование (ε = 0.2), метрика `accept`,
аналитический инференс:

| Режим | Оценщик | Смещение / SE | RMSE | Покрытие CI |
|---|---|---|---|---|
| `logged` | ips | 1.29 | 0.050 | 0.97 |
| `logged` | dr | 1.45 | 0.036 | 0.97 |
| `logged` | sndr | 1.46 | 0.037 | 0.97 |
| `logged` | dm | 0.60 | 0.025 | 0.77 |
| `estimated` | ips | 1.57 | 141 | 0.63 |
| `estimated` | dr | 1.25 | 44.8 | 1.00 |

Читается это так:

- **С логированными пропенсити оценщики работают.** Смещение везде ниже 3 SE,
  покрытие 95% интервала — 0.97.
- **DM даёт лучший RMSE, но недопокрытие (0.77).** Это ожидаемо: после добавления
  взаимодействий `x*a` модель исхода на этой среде специфицирована верно, поэтому DM
  эффективен; но аналитический интервал не учитывает ошибку модели исхода и потому
  слишком узок. Для DM берите `inference="bootstrap"`.
- **Оценённые пропенсити разваливаются** (RMSE 141 против 0.050). Логистическая
  модель не воспроизводит ступенчатые вероятности ε-greedy политики. Это свойство
  данных, а не библиотеки; библиотека обязана лишь честно об этом сообщить — и
  сообщает, помечая такие прогоны как ненадёжные.

## Границы применимости

Это **внутренняя проверка методологии** и защита от регрессий, а **не гарантия**
корректности на произвольных реальных данных:

- синтетическая среда упрощает реальный мир;
- на реальных логах истинное значение политики B неизвестно по определению —
  именно поэтому и нужны диагностики применимости;
- bootstrap и диагностики полезны, но не заменяют предметную валидацию
  конкретного прод-кейса и, в конечном счёте, онлайн-эксперимент.
