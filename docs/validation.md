# Проверка на симуляциях

Как узнать, что оценщик работает, если на реальных логах истинный ответ неизвестен? Нужно
прогнать его на данных, где истина известна точно, — много раз и в разных условиях.

[`examples/validate.py`](../examples/validate.py) делает это на синтетическом банке
[`ps.synthetic.OfferSimulator`](../src/policyscope/synthetic.py):

- четыре оффера, категориальный регион;
- две метрики: принятие (0/1) и выручка;
- по желанию — повторные визиты клиента с ненаблюдаемой склонностью соглашаться.

Истинное значение политики считается **аналитически**: вероятность принятия интегрируется по
клиентскому эффекту квадратурой Гаусса–Эрмита. Поэтому измеряемое смещение — это смещение
оценщика, а не шум эталона.

```bash
python examples/validate.py                     # все сценарии, ~7 минут
python examples/validate.py --runs 30 --strict  # с порогами приёмки (так запускается в CI)
```

## Сценарии

Во всех сценариях кандидат B — softmax-политика по другим скорам.

| Сценарий | Логирующая политика A | Пропенсити | Особенность |
|---|---|---|---|
| `logged` | ε-greedy, ε = 0.2 | в логах | базовый случай |
| `softmax` | softmax, T = 2 | в логах | умеренно тяжёлые веса |
| `weak_overlap` | softmax, T = 0.5 | в логах | пропенсити до 1e-10: перекрытия почти нет |
| `estimated` | ε-greedy, ε = 0.2 | **не залогированы** | модель пропенсити + bootstrap |
| `clustered` | ε-greedy, ε = 0.2 | в логах | 5 визитов на клиента, клиентский эффект |

## Как читать таблицу

Смещение, RMSE и покрытие считаются по прогонам, которые библиотека **не** пометила как
«ненадёжно»: именно в них пользователь делает вывод. Колонка «RMSE по всем прогонам» показывает,
что было бы, если игнорировать вердикт.

Приёмка (`--strict`) проверяет основной оценщик DR:

- смещение в пределах 3 MCSE;
- покрытие не ниже 0.90 с поправкой на погрешность Монте-Карло;
- в сценарии `weak_overlap` не меньше 30% прогонов помечены «ненадёжно».

## Выводы

1. **С логированными пропенсити DR несмещён, а 95% интервал покрывает истину в 92–98% прогонов**
   (`logged`, `softmax`, `clustered`). SNDR ведёт себя так же; IPS шумнее.
2. **Вердикт доверия отделяет катастрофы от пригодных оценок.**
   - В `weak_overlap` RMSE(DR) по всем прогонам равен 13 на метрике, лежащей в [0, 1]: отдельные
     веса достигают миллиардов.
   - Библиотека помечает такие прогоны как ненадёжные (46%) и не выдаёт по ним вывода.
   - Среди остальных RMSE = 0.05, а покрытие 0.96.
3. **Без логированных пропенсити оценка остаётся пригодной, но хуже.**
   - DR несмещён в пределах погрешности, покрытие bootstrap-интервала 0.88–0.94.
   - IPS и SNIPS заметно смещены, поэтому при оценённых пропенсити основным может быть только DR
     или SNDR. До 0.3 на этих же логах RMSE(DR) был 7.7.
4. **Кластерный интервал держит покрытие при повторных визитах.** О том, почему без
   кластеризации интервалы для `V(A)` и `V(B)` занижены, — в
   [методологии](methodology.md#4-доверительные-интервалы).
5. **DM даёт наименьший RMSE, потому что модель исхода здесь специфицирована близко к истине.**
   - На реальных данных так бывает не всегда, а интервал DM смещение модели не учитывает. Поэтому
     DM — только для сверки.
   - Проверка DR − DM в отчёте ловит случаи, когда модель исхода смещена (`tests/test_diagnostics.py`).

## Границы

- Синтетика проще реальности: нет дрейфа во времени, нет ненаблюдаемых конфаундеров, признаки
  известны. Проверка подтверждает, что методы реализованы верно и честно сообщают о проблемах. Она
  не гарантирует точность на любых данных.
- Прогонов в `estimated` меньше (bootstrap дорог), поэтому погрешность оценки покрытия там выше:
  примерно ±0.08.
