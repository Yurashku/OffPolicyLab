# Архитектура Policyscope

## Назначение

`Policyscope` — библиотека off-policy evaluation в постановке contextual bandit:
по логам поведения политики `A` оценить значение политики-кандидата `B`.
Целевые артефакты: `policy value`, `delta = V(B) − V(A)`, доверительный интервал,
метаданные значимости и диагностика применимости.

## Слои

```text
Контракт данных → Точечная оценка → Инференс → Диагностика/Отчёт
```

Границы ответственности:

- **Контракт данных** не знает про алгоритмы оценивания.
- **Точечная оценка** не содержит логики инференса.
- **Инференс** принимает оценщик как функцию и не меняет его математику.
- **Отчёт** собирает результаты в человекочитаемую форму и не считает статистику.

## Модули

| Модуль | Ответственность |
|---|---|
| `policyscope.data` | `BanditSchema`, `LoggedBanditDataset` — контракт и валидация логов |
| `policyscope.policies` | Политики и адаптеры для реальных моделей |
| `policyscope.estimators` | Формулы оценщиков, nuisance-модели, дизайн-матрица, валидаторы |
| `policyscope.nuisance` | Предсказания nuisance: in-sample, out-of-fold, источник пропенсити |
| `policyscope.estimate` | Единый диспетчер точечных оценок |
| `policyscope.inference` | Доверительные интервалы и значимость |
| `policyscope.diagnostics` | Диагностика весов и перекрытия |
| `policyscope.nuisance_diagnostics` | Качество nuisance-моделей |
| `policyscope.comparison` | Оркестрация: официальная точка входа |
| `policyscope.evaluator` | Объектная обёртка над оркестрацией |
| `policyscope.report` | Рендеринг результата и вердикт доверия |
| `policyscope.synthetic` | Синтетическая среда с аналитическим оракулом |
| `policyscope.validation` | Обвязка систематической проверки оценщиков |

## Реализованные оценщики

`on_policy`, `replay`, `ips`, `snips`, `dm`, `dr`, `sndr`, `switch_dr`.

Формулы и источники — в [`ope_methods_math_guide_ru.md`](ope_methods_math_guide_ru.md).
`replay` стоит особняком: он несмещён только при равномерной логирующей политике,
поэтому помечается предупреждением и не входит в наборы по умолчанию.

## Ключевые решения

### Единый источник формул

`estimators.estimator_contributions(method, ...)` возвращает построчные вклады
`psi_i` такие, что `mean(psi) == значение оценки`. Отсюда берут значение и точечные
оценщики, и аналитический инференс — поэтому они не могут разойтись. Для
самонормированных оценщиков (SNIPS, SNDR) возвращается дельта-метод-линеаризация
отношения: её среднее равно оценке, а разброс даёт корректную асимптотическую
дисперсию.

### Один путь через диспетчер

`estimate.estimate_point` всегда проходит одну схему: разрешить признаки и
пространство действий → получить nuisance-предсказания (внутренний fit либо
готовые, в том числе OOF) → собрать вклады → усреднить. Внутренний и cross-fit
пути пользуются одним кодом, а не двумя параллельными реализациями.

### Стабильная схема результата

`comparison.PolicyComparison` содержит все поля всегда; недоступные значения равны
`None`. Потребителю не нужно проверять наличие ключей.

### Два метода инференса

- `bootstrap` — парный кластерный percentile bootstrap. Nuisance переобучаются
  внутри каждой реплики, поэтому интервал учитывает и их неопределённость.
  Ресэмплер предвычисляет позиции строк по кластерам, что даёт `O(n)` на реплику.
- `influence` — аналитический интервал по вкладам с кластерно-робастной дисперсией.
  Не учитывает неопределённость nuisance: асимптотически корректен для DR-семейства
  при cross-fitting, антиконсервативен для DM.

### Скалярная награда как базовая абстракция

Единица оценки — одна скалярная метрика. Несколько метрик поддерживаются через
`compare_policies_multi_target(...)` как повторные запуски, а не как векторная
награда. Модель исхода обучается под конкретную метрику, поэтому переиспользование
одного nuisance-bundle между метриками отклоняется с ошибкой.

### Диагностика не заменяет инференс

Узкий интервал на данных без перекрытия политик остаётся бессмысленным. Поэтому
диагностика возвращается рядом с CI, а отчёт сводит её в явный вердикт доверия
(`надёжно` / `с осторожностью` / `ненадёжно`).

## Non-goals

- Обучение политик (off-policy learning) — только оценка.
- Slate/ranking и непрерывные пространства действий.
- Векторная награда как нативная сущность.
- Последовательные (multi-step RL) постановки.
