# Методология Policyscope

Документ описывает, что именно считает библиотека и почему так. Пользовательский путь —
в [README](../README.md), цифры проверки — в [validation.md](validation.md).

## 1. Постановка

Логи политики A — это строки $(x_i, a_i, r_i, p_i)$:

- $x_i$ — контекст (признаки клиента);
- $a_i$ — действие, которое выбрала A;
- $r_i$ — награда;
- $p_i = \pi_A(a_i \mid x_i)$ — пропенсити, то есть вероятность, с которой A выбрала это действие.

Пропенсити либо залогированы, либо оцениваются моделью.

Значение политики $\pi$ — средняя награда, которую она получила бы на тех же клиентах:

$$V(\pi) = \mathbb{E}_x \sum_a \pi(a \mid x)\, \mu(x, a), \qquad \mu(x, a) = \mathbb{E}[r \mid x, a].$$

Целевая величина — $\Delta = V(B) - V(\text{база})$. По умолчанию база — сама A, и тогда
$\hat V(A) = \bar r$ (средняя наблюдённая награда). Исключение — DM: у него
$\hat V(A) = \overline{\hat\mu(x_i, a_i)}$, прогноз той же модели на залогированных действиях. Тогда Δ
у DM — контраст двух прогнозов одной модели, и её систематическая ошибка частично сокращается. Если
передан `baseline`, его значение оценивается тем же оценщиком, что и $V(B)$.

## 2. Оценщики

Обозначения:

- $w_i = \pi_B(a_i \mid x_i) / p_i$ — вес важности;
- $\hat\mu$ — модель исхода;
- $dm_i = \sum_a \pi_B(a \mid x_i)\, \hat\mu(x_i, a)$.

| Оценщик | Формула | На что опирается |
|---|---|---|
| IPS | $\frac1n \sum_i w_i r_i$ | только пропенсити |
| SNIPS | $\sum_i w_i r_i \,/\, \sum_i w_i$ | только пропенсити (устойчив к масштабу весов) |
| DM | $\frac1n \sum_i dm_i$ | только модель исхода |
| DR | $\frac1n \sum_i \big[dm_i + w_i (r_i - \hat\mu(x_i, a_i))\big]$ | на обе модели |
| SNDR | $\frac1n \sum_i dm_i + \sum_i w_i (r_i - \hat\mu_i) \,/\, \sum_i w_i$ | на обе, поправка самонормирована |

**DR (по умолчанию)** состоятелен, если верна хотя бы одна из двух моделей. Его ошибка — это
произведение ошибок пропенсити и модели исхода (свойство двойной робастности).

**DM** точнее DR, если модель исхода верна, оценена эффективно (для Ridge при гетероскедастичном
шуме это не так) и данные покрывают то, что выбирает B: он заменяет шумный вес $w$ его проекцией на
признаки модели. Но его смещение целиком определяется моделью,
не убывает с ростом данных и по логам почти не обнаруживается. Поэтому DM не используется по
умолчанию, а выбирается явно (`estimator="dm"`):
- интервал считается bootstrap'ом с переобучением модели исхода;
- модель исхода должна быть встроенной;
- отчёт всегда предупреждает, что оценка держится только на модели.

В таблице согласия DM показывается точкой. Подробный разбор с цифрами — в
[estimators.md](estimators.md).

Каждый оценщик задан **построчными вкладами** $\psi_i$, такими что $\hat V = \bar\psi$:

- для IPS/DM/DR — это слагаемые формулы;
- для SNIPS/SNDR — дельта-метод-линеаризация отношения, например
  $\psi_i = \hat V + w_i (r_i - \hat V) / \bar w$ для SNIPS.

Из одних и тех же вкладов строятся и оценка, и аналитический интервал, поэтому разойтись они не
могут (`estimators.contributions`).

## 3. Nuisance-модели

Модель пропенсити $\hat\pi_A$ и модель исхода $\hat\mu$ от B не зависят. Они обучаются один раз
на `Evaluator` и переиспользуются для любого числа кандидатов.

**Cross-fitting.** Обе модели считаются out-of-fold по $k$ фолдам (по умолчанию 5): прогноз для
строки делает модель, которая её не видела. Фолды группируются по кластеру, а внутри
bootstrap-реплики — по исходной строке, иначе копии одной строки попадают в обучение и в прогноз.

**Модель исхода** по умолчанию выбирается по данным:
- бинарная награда — логистическая регрессия;
- неотрицательная награда с заметной долей нулей (выручка) — двухчастная модель
  $P(r>0 \mid z) \cdot \mathbb{E}[r \mid r>0, z]$: логистика × Gamma-GLM с log-связью;
- иначе — Ridge.

Дизайн-матрица — $[x,\ \text{onehot}(a),\ x \otimes \text{onehot}(a)]$: без блока взаимодействий
модель отличает действия только сдвигом.

Прогнозы непрерывных наград не обрезаются. До исправления обрезка по $[\min r, \max r]$, линейная
модель для выручки и база mean(r) в Δ у DM вместе смещали DM на величину до 3.5 его стандартных
ошибок (пара политик A3→B5). Единственное ограничение — у двухчастной модели: прогноз положительной
части не превышает наблюдённый максимум. Иначе log-связь в областях без данных экстраполирует
экспоненциально. Модель можно задать отдельно для каждой метрики (`outcome_model={"revenue": ...}`).

**Модель пропенсити** по умолчанию — мультиномиальная логистическая регрессия. Оценённое
пропенсити ограничено снизу **полом для каждого действия**:

$$\hat p_i \leftarrow \max\big(\hat p_i,\ c \cdot \text{доля действия } a_i \text{ в логах}\big), \qquad c = 0.1.$$

Зачем пол. Модель, не воспроизводящая ступенчатую логирующую политику (например, ε-greedy),
выдаёт пропенсити порядка $10^{-4}$ там, где на деле 0.05, и единичные веса в тысячи определяют
всю оценку. В прошлой версии на ε-greedy логах это давало RMSE(DR) = 7.7 при 0.03 на истинных
пропенсити. OOF-оценка с полом даёт 0.03–0.06.

Пол — доля от частоты действия, а не константа, чтобы не задавить редкие действия целиком.
Отчёт показывает:
- долю строк под полом;
- чувствительность Δ к полу ×0.5 и ×2 (считается из кеша, без переобучения).

## 4. Доверительные интервалы

### Аналитический (`inference="influence"`)

Оценка — среднее вкладов, поэтому её дисперсия — дисперсия среднего. Стандартная ошибка
кластерно-робастная (CR1):

$$\widehat{SE}^2 = \frac{G}{G-1} \cdot \frac{1}{n^2} \sum_{g=1}^G \Big(\sum_{i \in g} (\psi_i - \bar\psi)\Big)^2,$$

где $G$ — число кластеров (без кластеризации каждая строка — свой кластер). Критические значения
берутся из распределения Стьюдента с $G-1$ степенями свободы. Для $\Delta$ используются парные
вклады $\psi^B_i - \psi^A_i$: корреляция плеч учтена точно.

Кластеризация особенно важна для $V(A)$ и $V(B)$: склонность клиента входит в каждую его строку.
Для $\Delta$ при повторной рандомизации действия на каждом визите эффект клиента в парной
разности почти сокращается, так как $\mathbb{E}[w - 1 \mid x] = 0$. Но если действие назначается
клиенту один раз на все визиты, без кластеризации занижен и интервал для $\Delta$. Поэтому
`cluster=` нужно указывать всегда, когда строки клиента повторяются.

Когда интервал корректен:
- **с логированными пропенсити** — да. Ошибка модели исхода в DR входит лишь вторым порядком, и
  cross-fitting делает её асимптотически пренебрежимой;
- **с оценёнными пропенсити** — нет: интервал не учитывает ошибку их оценки. В симуляциях покрытие
  95% интервала DR было 0.89–0.93 при softmax-логировании T = 1 и до 0.75–0.81 при T = 0.5.
  Bootstrap с переобучением шире примерно на 17% и даёт 0.92–0.97;
- **для DM** аналитический интервал по вкладам $dm_i$ не учитывает ошибку оценки модели исхода и
  не реализован: только bootstrap.

### Bootstrap (`inference="bootstrap"`)

- Кластеры ресэмплируются целиком.
- На каждой реплике **заново обучаются** обе nuisance-модели (с cross-fitting), и считаются все
  оценщики, метрики и кандидаты.
- Интервал percentile; p-value центрированный:
  $\#\{|\theta^* - \hat\theta| \ge |\hat\theta|\} / B$ со сглаживанием $+1$.
- Зёрна реплик детерминированы, поэтому результат не зависит от `n_jobs`.

`inference="auto"` выбирает аналитический интервал при логированных пропенсити, а bootstrap — при
оценённых пропенсити и при `estimator="dm"`.

### Относительный прирост и MDE

- **Прирост** $V(B)/V(A) - 1$ — через log-ratio-линеаризацию
  $\psi^{lr}_i = \psi^B_i / \hat V_B - \psi^A_i / \hat V_A$. Интервал на лог-шкале
  экспоненцируется, поэтому он асимметричен и корректен при малых долях. Для неположительных $V$
  прирост не считается.
- **MDE** $\approx (t_{1-\alpha/2} + z_{0.8}) \cdot SE(\Delta)$ — эффект, который был бы
  обнаружен с вероятностью 80%. Указывается при выводе «разница не обнаружена».

## 5. Множественность: Romano–Wolf

Если метрик несколько (или в `compare` несколько кандидатов), p-value корректируются
stepdown-процедурой Romano–Wolf (2005, 2016). Она контролирует FWER — вероятность хотя бы одного
ложного «значимо». В отличие от Бонферрони и Холма, процедура учитывает зависимость гипотез: все
метрики и кандидаты оцениваются на одних логах, и при сильной корреляции поправка почти не
штрафует.

Алгоритм:
1. Гипотезы упорядочиваются по убыванию $|t_j|$.
2. Для $j$-й гипотезы $p^{adj}_j = \max\big(p^{adj}_{j-1},\ P^*(\max_{l \ge j} |t^*_l| \ge |t_j|)\big)$.

Нулевое распределение $t^*$:
- при аналитическом интервале — gaussian multiplier bootstrap по кластерным суммам вкладов
  $t^*_j = \sum_g \xi_g S_{gj} / (n\, SE_j)$, $\xi_g \sim N(0,1)$, без переобучения моделей.
  При фиксированных суммах это ровно $N(0, R)$ с $R$ из $S^\top S$, поэтому сэмплируется сразу
  $J$-мерное нормальное;
- при bootstrap — центрированные реплики $(\Delta^*_j - \hat\Delta_j)/sd_j$.

Вывод по метрике по-прежнему опирается на её собственный интервал. Скорректированное p-value
нужно, когда решение принимается «если хоть одна метрика значимо выросла».

## 6. Диагностика и вердикт

### Триангуляция оценщиков

Разности оценщиков — средние построчных величин с известным матожиданием:

- $\text{DR} - \text{IPS} = \overline{dm_i - w_i \hat\mu(x_i, a_i)}$. Матожидание равно 0 при
  верных пропенсити и **любой** OOF-модели исхода. Значимое отличие означает, что пропенсити
  неверны или B уходит туда, где A не действует.
- $\text{DR} - \text{DM} = \overline{(w_i - 1)(r_i - \hat\mu(x_i, a_i))}$ — разность показанных в
  отчёте Δ (у DM база — прогноз модели). Матожидание равно 0 при верной модели исхода и **любых**
  весах. Значимое отличие означает, что модель исхода смещена.

Для SN-оценщиков используются нормированные веса $w/\bar w$ (SNDR − SNIPS, SNDR − DM). Веса берутся
те, которые реально использует основной оценщик (с полом).

Статус проверки:

| Статус | Условие |
|---|---|
| провал | интервал разности (z = 2.58) не содержит 0 **и** \|разность\| > 0.5·SE(Δ) |
| значимого расхождения нет | в отчёте указывается граница: расхождение какой величины данные не исключают |
| мало данных | ESS < 30 |

Порог существенности не даёт тревоге срабатывать при большом $n$ из-за ничтожных, но значимых
расхождений. Граница в статусе «нет расхождения» не позволяет выдать отсутствие мощности за
«проверка пройдена». Обычно погрешность проверки сопоставима с погрешностью самой Δ: проверка
ловит грубые ошибки пропенсити или модели исхода, но не тонкие.

Серьёзность провала зависит от основного оценщика:

| Основной | DR−IPS провалена | DR−DM провалена | Обе |
|---|---|---|---|
| IPS / SNIPS | ненадёжно | — | ненадёжно |
| DR / SNDR | осторожно (держится на модели исхода) | к сведению при логированных пропенсити, иначе осторожно | ненадёжно |
| DM | — | ненадёжно | ненадёжно |

Прохождение проверки не подтверждает модель. Шум проверки DR − DM порядка SE(DR), поэтому она
замечает только грубые смещения DM, порядка нескольких его стандартных ошибок. Использовать её
как разрешение выбрать DM нельзя: процедура «DM, если проверка пройдена» имеет реальный уровень
около 0.5 вместо 0.05. При тяжёлых хвостах весов проверка DR − IPS срабатывает и при точных
логированных пропенсити: это значит, что хвост весов не попал в выборку, а не что пропенсити
неверны.

### Проверки, не зависящие от B

- **Колонка пропенсити — вероятность?** Для любой политики A
  $\mathbb{E}[\mathbb{1}\{A=a\}/p] = P(\pi_A(a \mid x) > 0) \le 1$ для каждого действия. Значимое
  превышение блокирует вывод. Типичная причина — передана вероятность отклика.
- **Исследует ли A?** $\overline{1/p}$ — среднее число действий, которым A оставляет шанс. Если
  оно меньше 1.2 (или средний максимум оценённой вероятности больше 0.95), A детерминирована.
  Тогда вывод блокируется, если B кладёт на действие A меньше 95% массы.

### Перекрытие и устойчивость

- **Носитель:** $\mathbb{E}[w] = 1 - (\text{масса } B \text{ там, где } \pi_A = 0)$. Значимый
  дефицит больше 5% даёт «осторожно», больше 20% — «ненадёжно».
- **ESS** $= (\sum w)^2 / \sum w^2$: меньше 30 — «ненадёжно», доля меньше 5% — «осторожно».
- **Концентрация:** один кластер или строка даёт больше половины дисперсии Δ.
- **Чего вердикт не гарантирует.** Он защищает от катастрофических ошибок: при слабом перекрытии
  блокирует прогоны, где RMSE в десятки раз больше. Но при тяжёлых хвостах весов интервал DR в
  незаблокированных прогонах может недопокрывать с одной стороны (0.81–0.94 в симуляциях), и
  «надёжно» там откалибровано не лучше, чем «с осторожностью».
- **Утечка исхода:** признак, почти идеально предсказывающий награду (AUC > 0.97 или |r| > 0.95).
  В авто-режиме он исключается, при явном указании — предупреждение.

### Вердикт

Вердикт определяется самой серьёзной находкой:

| Есть находка уровня | Вердикт |
|---|---|
| block | ненадёжно |
| caution | с осторожностью |
| только info или ничего | надёжно |

При вердикте «ненадёжно» вывод не делается, даже если интервал не накрывает ноль. Пороги
собраны в `ps.Thresholds`.

### Коды находок

Код — стабильный идентификатор для пайплайнов (`report.to_dict()["findings"]`, поле `code`);
текст и совет в отчёте — для людей. Уровни: **block** — вывод не делается, **caution** —
«с осторожностью», **info** — к сведению.

| Код | Уровень | Когда возникает |
|---|---|---|
| `too_few_rows` | block | В логах меньше 30 строк. |
| `constant_metric` | block | Метрика в логах не меняется — оценивать нечего. |
| `non_finite_estimate` | block | Основной оценщик дал нечисловое значение или интервал. |
| `propensity_not_probability` | block | Колонка пропенсити нарушает тождество $\mathbb{E}[\mathbb{1}\{A=a\}/p] \le 1$. |
| `deterministic_logging` | block | A почти не исследует, а кандидат от неё отличается. Для базовой политики — `deterministic_logging_baseline`. |
| `support_deficit` | caution / block | Средний вес значимо меньше 1: масса кандидата там, где A не действует. Если дефицит больше 20% — block. |
| `critically_low_ess` | block | Эффективный размер выборки меньше 30. |
| `low_ess` | caution | ESS меньше 5% выборки. |
| `weights_inflated` | caution | Средний вес значимо больше 1: пропенсити занижены. |
| `propensity_check_failed` | block для IPS/SNIPS, caution для DR/SNDR | IPS и DR существенно расходятся. |
| `outcome_check_failed` | block для DM; caution при оценённых пропенсити; иначе info | DR и DM существенно расходятся: модель исхода смещена. |
| `both_models_rejected` | block | Провалены обе проверки — DR не защищён. |
| `variance_concentration` | caution | Один клиент или строка даёт больше половины дисперсии Δ. |
| `propensity_estimated` | caution | Пропенсити не залогированы и восстановлены моделью. |
| `propensity_floor_active` | caution | Больше 5% строк упёрлись в пол пропенсити. |
| `floor_sensitive` | caution | Δ меняется больше чем на SE при изменении пола вдвое. |
| `rare_actions_in_folds` | caution | Действие не встретилось в обучающем фолде модели пропенсити. |
| `influence_with_estimated_propensity` | caution | Аналитический интервал запрошен при оценённых пропенсити. |
| `model_based_estimate` | caution | Основной оценщик — DM: оценка держится только на модели исхода. |
| `bootstrap_failures` | caution / block | Часть bootstrap-реплик не посчиталась. Если их больше 10% — block. |
| `few_clusters` | caution | Кластеров меньше 30. |
| `cluster_not_set` | caution | Колонка вроде `client_id` повторяется, но `cluster` не указан. |
| `outcome_like_features` | caution | Явно заданный признак почти идеально предсказывает награду. |
| `auto_features` | info | Признаки выбраны автоматически; в тексте — список использованных и пропущенных. |

## 7. Предпосылки и ограничения

- **Нет ненаблюдаемых конфаундеров.** Всё, что влияло и на выбор A, и на награду, есть среди
  признаков. По данным это не проверяется.
- **Независимость кластеров** и стабильность среды между логированием и внедрением.
- **B не обучалась на оцениваемых логах.**
- **Бандитская постановка.** Решение влияет только на награду этой строки: последовательные
  эффекты (RL) не моделируются.

## 8. Устройство пакета

| Модуль | Ответственность |
|---|---|
| `data.py` | валидация логов, кодирование действий и категорий, авто-признаки, детектор утечки |
| `policy.py` | приведение любой политики к матрице $(n, k)$ по меткам действий; `greedy`/`softmax`/`epsilon_greedy` |
| `estimators.py` | только формулы: построчные вклады пяти оценщиков, ESS |
| `nuisance.py` | out-of-fold модели пропенсити и исхода, пол пропенсити |
| `inference.py` | CR1-ошибка, t-квантили, кластерный bootstrap, Romano–Wolf |
| `diagnostics.py` | находки, триангуляция, перекрытие, вердикт |
| `evaluator.py` | `Evaluator`, `evaluate`, `compare`: оркестрация и кеш моделей |
| `report.py` | `Report`, `MetricReport`, `Leaderboard`: markdown, dict/JSON, DataFrame |
| `synthetic.py` | симулятор офферов с аналитическим оракулом |

Инварианты, которые держат тесты:

- **Формулы живут в одном месте.** Это `estimators.contributions`; точечная оценка и интервал
  берут их оттуда.
- **Никаких молчаливых подстановок.** Любой откат (пол пропенсити, исключённый признак) виден в
  отчёте.
- **Политика вычисляется один раз на полных логах.** Фолды и реплики индексируют матрицу по
  позиции.
- **Схема `to_dict()` стабильна.** Ключи присутствуют всегда; нет значения — `None`.
- **Изменение математики сопровождается тестом корректности против известной истины**
  (`tests/test_statistical.py`), а не smoke-тестом.
